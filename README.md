# Учёт актов и оплат

Текущая версия — **1.9.3**. Исправлены печать операций в Word и Excel, перенос длинных таблиц и денежные значения в Excel. Добавлены компактные меню действий и иконка приложения. Сохранены серые и белые оплаты, общий показатель С/Р, квартальные налоги, акты вне, ежемесячные и почасовые акты, фильтры и личные настройки интерфейса.

Приложение для Windows 10/11, рассчитанное на один компьютер: заказчики и подрядчики, объекты, договоры, сметы, выполненные работы, акты, счета, авансы, расходы и задолженность. Работает с локальной базой.

[Скачать приложение для Windows](https://github.com/SCP701/Uchet/releases/latest/download/AktiOplaty-Windows.zip) · [Все выпуски](https://github.com/SCP701/Uchet/releases)

## Первый запуск

1. Скачайте и распакуйте `AktiOplaty-Windows.zip` в обычную папку, например «Документы\Учёт».
2. Запустите `AktiOplaty.exe`. Файл `Updater.exe` оставьте рядом.
3. Добавьте свою организацию, контрагентов и объекты. Затем можно вводить договоры, акты и оплаты.

Рабочие данные хранятся отдельно от программы, в `%LOCALAPPDATA%\WorkLedger`. Для сохранности используйте резервные копии в приложении. Git, Python и инструменты разработчика для работы с приложением не нужны.

## Обновление

Откройте **«Обновления» → «Проверить обновления»**. Если доступна новая версия, нажмите **«Обновить»**. Источник `SCP701/Uchet` уже указан в программе. Обновлятор проверяет подпись, контрольные суммы и совместимость с базой, создаёт резервную копию и заменяет файлы программы. После завершения приложение запускается снова.

## Изменения 1.9.1–1.9.3

Основные действия остаются на компактной панели каждого раздела. Остальные команды находятся в меню «Действия», «Документы» и «Данные», а настройки интерфейса и резервные копии — в верхнем «Меню». Приложение получило иконку документа для запуска, окна и панели задач.

В Word и Excel каждая операция занимает отдельную строку основного акта. Длинные таблицы Word повторяют заголовок на следующих страницах и сохраняют строки целиком. Денежные столбцы Excel содержат числа, пригодные для суммирования. CSV защищает текст от интерпретации как формул и сохраняет его при повторном импорте.

Исполняемые файлы и ярлыки, добавленные как вложения, сохраняются в базе и резервных копиях, но не запускаются из приложения.

## Серые оплаты и общий итог С/Р

В группе «Финансы» есть раздел «Серые оплаты». Выберите «Акт вне» в форме оплаты — контрагент, валюта и связанные поля подставятся. «Вид оплаты» позволяет выбрать белую или серую; для серой обязателен акт вне. Чтобы уменьшить долг по акту, нажмите «Зачесть оплату».

На «Обзоре» карточка С/Р показывает все полученные белые и серые оплаты за всё время в выбранной валюте, включая авансы и архив. Каждый исходный платёж учитывается один раз. Квартальный налог считается только по белой части; серые оплаты исключаются. Например: белые 10 000 + серые 3 500 = С/Р 13 500, налог 2 000.

Старые смешанные оплаты сохраняются одной записью и показывают белую и серую части. Общие отчёты и сверка включают полную сумму. Импорт отклоняет строки, которые потеряли бы распределения и изменили цвет оплаты.

## Налоги по кварталам

В группе «Финансы» откройте «Налоги» и выберите год, квартал и валюту. По умолчанию выбран последний завершённый квартал.

Белые поступления считаются по датам фактически полученных белых входящих оплат за три месяца. Включаются белые авансы и белые входящие оплаты в архиве; валюты считаются отдельно. Встроенный расчёт использует 20% общей суммы, с округлением до копеек после суммирования; остаток — поступления минус налог. Пример: 10 000 → налог 2 000 → остаток 8 000.

Ниже показаны оплаты, вошедшие в расчёт. Двойной щелчок или Enter открывает оплату. Пересчёт сохраняет рабочую базу без изменений. Показ и скрытие раздела доступны через «Интерфейс»; раздел входит в набор «Акты и оплаты».

## Акты вне

Раздел «Акты вне» поддерживает создание и редактирование, работы и часы, реквизиты, печать, Word/Excel, оплаты и сверку. Он входит в общий учёт. Отдельный отчёт «Акты для налогового учёта» выбирает обычные подписанные акты; квартальный раздел «Налоги» считает фактически полученные входящие оплаты.

## Фоновое создание ежемесячных актов

Исправлена первая настройка задачи Windows. При включённом ежемесячном обслуживании программа повторяет настройку при запуске; акты создаются 1-го числа в 00:05 по Минску и при следующем входе пользователя, если ПК был выключен.

## Акты Word

В разделе «Акты» выберите запись. «Позиции акта» позволяет заполнить работы, единицы, количество и цены; при сохранении итог становится суммой акта с проверкой уже внесённых оплат. «Акт Word» создаёт `.docx` по образцу: каждая операция занимает отдельную строку основного акта, с реквизитами, подписями и суммой прописью. Форма рассчитана на **без НДС**. Для сохранения документа Word на компьютере не требуется.

Если работ много, таблица продолжается на следующих страницах с повторением заголовков. Строки операций сохраняются целиком, общий итог не меняется. Акты из смет получают копию позиций, которая сохраняется независимо от дальнейших изменений сметы.

## Печать актов

Кнопка «Печатная форма» и предпросмотр открывают акт на вертикальном A4: реквизиты сторон, отдельная строка каждой операции, количество, цена, сумма, общий итог, сумма прописью и подписи. При продолжении повторяется шапка таблицы.

Для старых актов с одной общей суммой пронумерованные операции отображаются отдельно; неизвестные цены и суммы отмечаются прочерками. Программа сохраняет исходный общий итог и не распределяет стоимость между операциями. Цены отдельных работ можно заполнить через «Позиции акта». Печать не изменяет рабочую базу, оплаты и задолженность.

## Фильтры

В списках доступны отбор по контрагенту, объекту, валюте и состоянию, быстрые периоды и кнопка **«Сбросить»**. Для каждого раздела показываются применимые условия. Архивные контрагенты доступны для просмотра финансовой истории.

Поиск проверяет несколько слов одновременно, включая примечания, связанные записи и рассчитанные суммы. Регистр, «е»/«ё» и неразрывные пробелы не мешают поиску. **Ctrl+F** открывает поиск, **Ctrl+Shift+R** сбрасывает условия.

Период включает оба указанных дня; нижнюю и верхнюю границы можно включать независимо. Для работ используется дата сметы. В отчётах поиск применяется до расчёта итогов; сальдо в сверке с поисковым запросом относится к найденным документам. Архивирование финансовых записей сохраняет их в бухгалтерских суммах.

Ежемесячное обслуживание задаётся в карточке контрагента: сумма, валюта, описание работ и первый месяц. Приложение создаёт акты за наступившие месяцы и проверяет, что повторные запуски не создают дубликаты.

## Публикация подготовленного выпуска

В `release-assets/` лежат три подписанных файла обновления и архив первого запуска. При их добавлении в ветку `main` GitHub Actions проверяет подпись встроенным публичным ключом и содержимое обоих архивов, затем создаёт выпуск с тегом из манифеста: например `v1.9.3` для версии `1.9.3.0`.

Если выпуск с этим тегом уже опубликован, проверка сравнит все файлы с подготовленными. Совпадающий выпуск останется без изменений; при различии проверка завершится ошибкой. Файлы и описание существующего выпуска не перезаписываются.

Приватный ключ подписи хранится только у разработчика. В этом репозитории есть лишь публичный ключ `update-public-key.pem`; база, вложения и личные настройки сюда не включаются. Ручной повтор проверки доступен на вкладке **Actions → Publish signed Windows release → Run workflow** для ветки `main`.

## Сборка из исходников

Исходники приложения и обновлятора находятся в этом репозитории. Для сборки нужен Windows с .NET Framework 4.x; компилятор выбирается из системной папки .NET Framework.

Из папки репозитория выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

Команда собирает приложение, обновлятор и инструмент выпуска, затем запускает проверки. Результат находится в `dist/`; проверочные данные создаются в `.verification/` и `.uverify/`.

`publish-release.ps1` готовит подписанное обновление из сборки с помощью оригинального локального ключа подписи. Путь к нему задаётся параметром `-SigningKeyPath`. Приватный ключ и рабочую базу нельзя добавлять в репозиторий.
