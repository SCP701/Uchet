# Учёт актов и оплат

Текущая версия — **1.6.2**. Включает расширенные фильтры, ежемесячные акты обслуживания, почасовые акты, документы Word и личные настройки интерфейса.

Приложение для Windows 10/11, рассчитанное на один компьютер: заказчики и подрядчики, объекты, договоры, сметы, выполненные работы, акты, счета, авансы, расходы и задолженность. Работает с локальной базой.

[Скачать приложение для Windows](https://github.com/SCP701/Uchet/releases/latest/download/AktiOplaty-Windows.zip) · [Все выпуски](https://github.com/SCP701/Uchet/releases)

## Первый запуск

1. Скачайте и распакуйте `AktiOplaty-Windows.zip` в обычную папку, например «Документы\Учёт».
2. Запустите `AktiOplaty.exe`. Файл `Updater.exe` оставьте рядом.
3. Добавьте свою организацию, контрагентов и объекты. Затем можно вводить договоры, акты и оплаты.

Рабочие данные хранятся отдельно от программы, в `%LOCALAPPDATA%\WorkLedger`. Для сохранности используйте резервные копии в приложении. Git, Python и инструменты разработчика для работы с приложением не нужны.

## Обновление

Откройте **«Обновления» → «Проверить обновления»**. Если доступна новая версия, нажмите **«Обновить»**. Источник `SCP701/Uchet` уже указан в программе. Обновлятор проверяет подпись, контрольные суммы и совместимость с базой, создаёт резервную копию и заменяет файлы программы. После завершения приложение запускается снова.

## Акты Word

В разделе «Акты» выберите запись. «Позиции акта» позволяет заполнить работы, единицы, количество и цены; при сохранении итог становится суммой акта с проверкой уже внесённых оплат. «Акт Word» создаёт `.docx` по образцу: основной акт и приложение с подробным списком работ, реквизитами, подписями и суммой прописью. Форма рассчитана на **без НДС**. Для сохранения документа Word на компьютере не требуется.

Номер и итог совпадают на обеих страницах. Если работ много, приложение продолжается на следующих страницах с повторением заголовков таблицы. Акты из смет получают копию позиций, которая сохраняется независимо от дальнейших изменений сметы.

## Печать актов

Кнопка «Печатная форма» и предпросмотр открывают акт на вертикальном A4: реквизиты сторон, отдельная строка каждой операции, количество, цена, сумма, общий итог, сумма прописью и подписи. При продолжении повторяется шапка таблицы.

Для старых актов с одной общей суммой пронумерованные операции отображаются отдельно; неизвестные цены и суммы отмечаются прочерками. Программа сохраняет исходный общий итог и не распределяет стоимость между операциями. Цены отдельных работ можно заполнить через «Позиции акта». Печать не изменяет рабочую базу, оплаты и задолженность.

## Фильтры

В списках доступны отбор по контрагенту, объекту, валюте и состоянию, быстрые периоды и кнопка **«Сбросить»**. Для каждого раздела показываются применимые условия. Архивные контрагенты доступны для просмотра финансовой истории.

Поиск проверяет несколько слов одновременно, включая примечания, связанные записи и рассчитанные суммы. Регистр, «е»/«ё» и неразрывные пробелы не мешают поиску. **Ctrl+F** открывает поиск, **Ctrl+Shift+R** сбрасывает условия.

Период включает оба указанных дня; нижнюю и верхнюю границы можно включать независимо. Для работ используется дата сметы. В отчётах поиск применяется до расчёта итогов; сальдо в сверке с поисковым запросом относится к найденным документам. Архивирование финансовых записей сохраняет их в бухгалтерских суммах.

Ежемесячное обслуживание задаётся в карточке контрагента: сумма, валюта, описание работ и первый месяц. Приложение создаёт акты за наступившие месяцы и проверяет, что повторные запуски не создают дубликаты.

## Публикация подготовленного выпуска

В `release-assets/` лежат три подписанных файла обновления и архив первого запуска. При их добавлении в ветку `main` GitHub Actions проверяет подпись встроенным публичным ключом и содержимое обоих архивов, затем создаёт выпуск с тегом из манифеста: например `v1.6.2` для версии `1.6.2.0`.

Если выпуск с этим тегом уже опубликован, проверка сравнит все файлы с подготовленными. Совпадающий выпуск останется без изменений; при различии проверка завершится ошибкой. Файлы и описание существующего выпуска не перезаписываются.

Приватный ключ подписи хранится только у разработчика. В этом репозитории есть лишь публичный ключ `update-public-key.pem`; база, вложения и личные настройки сюда не включаются. Ручной повтор проверки доступен на вкладке **Actions → Publish signed Windows release → Run workflow** для ветки `main`.

## Сборка из исходников

Исходники приложения и обновлятора находятся в этом репозитории. Для сборки нужен Windows с .NET Framework 4.x; компилятор выбирается из системной папки .NET Framework.

Из папки репозитория выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

Команда собирает приложение, обновлятор и инструмент выпуска, затем запускает проверки. Результат находится в `dist/`; проверочные данные создаются в `.verification/` и `.uverify/`.

`publish-release.ps1` готовит подписанное обновление из сборки с помощью оригинального локального ключа подписи. Путь к нему задаётся параметром `-SigningKeyPath`. Приватный ключ и рабочую базу нельзя добавлять в репозиторий.
